[P343|Normal] - 1d：调整为“每 tick 最多 1024 笔事务，同时增加确定性事务工作量上限”。

[P441|Normal] - **Q4**：足以支撑 Stage 2A 收口。五条判据（最优性对拍、唯一性、预算上界、重算率 ≤5%、阻塞率 ≤1%）全部实测 PASS，且附带取消语义与冲突合并（tx_id 全序）定义完整；已知限定（单线程/单平台/并发队列压测）已明确转 Stage 2B，不影响本阶段退出。
[P442|Normal] - **Q5**：与 NEW-20（机制 B 三硬约束细化、budget_yield_count 分离、单 tick 原子搜索）及 NEW-23（两阶段 stale 判定、重算上限、MarkBlocked 兜底、代价默认不触发）联动一致，未见遗漏或矛盾。取消 = 队列移除 + ID 不复用 + 已搜索中止不发布，与 NEW-20 对齐；冲突按 tx_id 全序串行不合并，确定性可接受。
[P443|Normal] - 新增风险（如有）：
[P444|Normal] - 重复展开率阈值若长期不正式锁定，后续地图形态变化可能导致“默认 B vs 切换 A”的决策漂移。
[P445|Normal] - 当前证据仅覆盖单线程单机；并发请求队列下的最坏单 tick 与假前向进展行为未见证据，须在 Stage 2B 补测。
[P446|Normal] - Edge 有向语义若未及时入数据字典，场景/测试构造仍可能复现“单向网格导致高阻塞率”类事故。
[P449|Normal] ## ADR-NEW-24 裁决记录
[P450|Normal] - 裁决：有条件采纳
[P452|Normal] - 理由：
[P453|Normal] CSR 的确定性存储顺序、A* 的稳定排序规则及机制 B 的预算递增方向合理，现有 G5 与 churn 数据也为 Stage 2A 提供了正向实测证据。
[P454|Normal] 但目前仍有几个影响正确性边界的问题：曼哈顿启发式的一致性条件、允许 reopen 时 L=|V| 的展开上限是否成立，以及机制 B 重复展开率阈值尚未定案。
[P455|Normal] 因此可以认可主要设计方向，但必须关闭以下条件，才能将 ADR 转为无附加条件的 Accepted；Stage 2A 实施面可以按 5/5 收口，不代表所有跨阶段验证已经完成。
[P457|Normal] - 验证条件 / 修改要求：
[P459|Normal] 1. 启发式的可采纳性与一致性条件必须写成可检查的不变量。
[P460|Normal] 不能只描述“边代价下限 ≥ 1 mm 等价长度”。
[P461|Normal] 对每条有向边 u→v，应保证 h(u) ≤ cost(u,v) + h(v)。
[P462|Normal] 若使用曼哈顿距离，必须明确边代价与端点曼哈顿距离之间的下界关系；道路边存在斜向、跨格或动态代价时，也必须满足该关系。
[P463|Normal] 若无法保证一致性，应明确允许 reopen，并重新证明展开次数上界。
[P465|Normal] 2. 重新核实机制 B 的 L=|V| 上限。
[P466|Normal] ADR 同时规定“节点首次展开即闭合”和“仅当 g 严格更小时允许 reopen”。
[P467|Normal] 如果允许 reopen，则同一节点可能被展开多次，不能仅凭节点总数推导总展开次数不超过 |V|。
[P468|Normal] 建议二选一：
[P469|Normal] a. 证明启发式一致，且实现中不需要 reopen；或
[P470|Normal] b. 保留 reopen，但重新定义可证明的展开上限 L，并给出相应的预算递增与终止上界。
[P471|Normal] 必须增加一个会触发 reopen 的测试场景，验证不会因 L=|V| 提前 MarkBlocked 或错误终止。
[P473|Normal] 3. 明确 A* open 集的完整确定性语义。
[P474|Normal] (f,h,node_id) 可以作为节点优先级排序键，但需要定义同一 node_id 存在多个候选条目时的去重、更新和过期条目处理。
[P475|Normal] 对相同 g 的多条前驱路径，应明确采用首次发现保留，还是按稳定的 parent_node_id / edge_id 规则裁决。
[P476|Normal] 增加等代价多路径、重复入队、相同排序键和乱序输入测试。
[P477|Normal] 不允许依赖不稳定排序或容器偶然迭代顺序决定最终 predecessor。
[P479|Normal] 4. 机制 B 重复展开率阈值暂不定为正式常量。
[P480|Normal] 当前 0.53 只有一个 200×200 角到角压力场景，不能证明它代表一般负载分布。
[P481|Normal] 建议先将 0.53 记录为基准观测值，不据此直接认定机制 B 已达到切换阈值。
[P482|Normal] Stage 2B 前补充不同图规模、路径长度、障碍密度、请求分布和拓扑 churn 组合测试，再确定阈值。
[P483|Normal] 阈值必须使用确定性工作量指标，不得根据墙钟耗时动态切换机制。
[P484|Normal] 同时统一重复展开率的分子、分母和统计窗口定义。
[P486|Normal] 5. Edge 有向语义写入正式数据字典。
[P487|Normal] 明确 Edge 表示有向边 from_node_id → to_node_id。
[P488|Normal] 双向通行必须显式建立两条独立有向边，不隐式推导反向边。
[P489|Normal] 两个方向拥有独立 edge_id，可具有不同 cost、通行状态和事务变更记录。
[P490|Normal] CSR 邻接序按 edge_id 稳定排序；删除或修改一个方向，不得隐式影响反方向。
[P491|Normal] 补充单向边、双向边、单方向删除和方向代价不同的测试。
[P493|Normal] 6. 补齐取消和事务冲突语义的直接测试证据。
[P494|Normal] ADR 中的取消语义包括队列移除、请求 ID 不复用、已开始搜索的请求中止且不发布。
[P495|Normal] 冲突语义包括 tx_id 全序串行发布、影响区域重叠时后续事务拒绝并入队重试。
[P496|Normal] 当前退出核对表没有列出这些行为的独立测试结果，不能仅凭文字定义认定已验证。
[P497|Normal] 建议为上述行为增加确定性测试，并纳入对应阶段门禁。
[P499|Normal] 7. 补充预算让步与路网过期交错场景。
[P500|Normal] 测试同一个请求先发生 budget yield、再遇到拓扑变更、随后 stale recompute 的完整过程。
[P501|Normal] 明确 stale recompute 后 budget_yield_count 是否重置、如何处理 request_id / attempt_id、使用哪个 graph_version。
[P502|Normal] 两类计数器必须保持独立，不能把路网失效导致的重算误记为预算让步。
[P503|Normal] 该场景还应覆盖保存、恢复后继续运行的强读档等价。
[P505|Normal] 8. 补充 CSR 容量边界检查。
[P506|Normal] offsets 使用 u32，必须定义邻接条目总数超过 u32::MAX 时的确定性失败行为。
[P507|Normal] 不得发生截断、回绕或部分发布。
[P508|Normal] 整表重建失败时，旧 CSR 版本必须保持有效。
[P510|Normal] 9. 将尚未完成的跨阶段验证保留为明确门禁。
[P511|Normal] 双平台一致性、并发队列压力、让步路径强读档等价、R3/R4 验证不得因 Stage 2A 退出而标记完成。
[P512|Normal] 后续验证结果应进入 benchmarks，并与对应 ADR 条件逐项关联。
[P514|Normal] - 对 Q1-Q5 的逐项意见：
[P516|Normal] Q1：有条件接受。
[P517|Normal] (f,h,node_id) 升序是合理且可复现的平局打破规则。
[P518|Normal] h 升序在 f 相同时等价于优先较大的 g，即优先较深前沿。
[P519|Normal] G5 报告中的角到角约 398 次展开，为该排序策略提供了正向证据。
[P520|Normal] 但必须补齐启发式一致性、重复入队、相同节点候选和 predecessor 裁决规则。
[P521|Normal] 当前证据不足以证明所有合法路网结构下均能唯一地产生相同路径。
[P523|Normal] Q2：参数方向有条件接受；重复展开率阈值暂缓定案。
[P524|Normal] g=2、L=|V|、B_k=min(b·2^k,L) 具备简单、可复现的确定性预算规则。
[P525|Normal] 40k 节点场景中，机制 B 为 4 ticks，重复展开率 0.53，累计展开 846，丢弃展开 448；解析上界为 11 ticks，实测没有超出。
[P526|Normal] 但 L=|V| 依赖单请求展开次数不超过节点数的前提，而 reopen 语义尚未证明满足该前提。
[P527|Normal] 因此在修正 L 的证明之前，不应把这组参数视为完整正确性定案。
[P528|Normal] 0.53 暂作观测基线，不建议现在设定正式切换阈值；补充多场景数据后再确定。
[P529|Normal] 机制 A 可保留为确定性切换路径，但切换条件不得依赖墙钟时间。
[P531|Normal] Q3：接受。
[P532|Normal] Edge 是有向边；双向通行通过两条独立有向边表示。
[P533|Normal] 该定义与 G5 churn 报告中单向网格导致部分请求不可达的事故教训一致。
[P534|Normal] 应写入数据字典，并明确反向边拥有独立 edge_id、cost 和通行状态。
[P536|Normal] Q4：有条件接受。
[P537|Normal] 现有五项指标足以支持 Stage 2A 的实施面退出：最优性对拍、结果唯一性、预算上界、阻塞率和过期重算率均有报告或原始数据支撑。
[P538|Normal] 但五项通过不代表 ADR 中取消语义、事务冲突语义和跨阶段强读档等价均已验证。
[P539|Normal] 建议正式记录为“Stage 2A 实施退出 5/5；遗留验证转入 Stage 2B/R3/R4”，不得写成全部架构验证完成。
[P541|Normal] Q5：存在遗漏，需要补充联动说明。
[P542|Normal] 与 ADR-NEW-20：
[P543|Normal] - budget_yield_count 与 stale_recompute_count 必须独立。
[P544|Normal] - 机制 B 每次预算让步从头搜索，必须定义请求状态、预算递增次数和图版本之间的关系。
[P545|Normal] - reopen 对展开上界的影响必须与机制 B 的 L 一起解决。
[P546|Normal] - 让步状态保存恢复等价仍需专项测试。
[P548|Normal] 与 ADR-NEW-23：
[P549|Normal] - stale 检查的 AABB broad-phase 与 edge_id narrow-phase 必须保持一致。
[P550|Normal] - 拓扑变化、道路关闭、删除和动态代价变化的过期语义不能混为一类。
[P551|Normal] - stale recompute 不得错误增加预算让步计数。
[P552|Normal] - 多笔事务影响区域聚合、请求搜索期间路网版本变化以及结果发布前再次 stale_check 的边界需要明确。
[P554|Normal] 当前 churn 数据有 200 请求、10 笔拓扑事务、1100 次 stale 检查、3 次重算，重算率 0.0027、阻塞率 0。
[P555|Normal] 但该场景 budget_yield_count=0，尚未覆盖“预算让步与路网过期同时发生”的组合情形。
[P557|Normal] - 新增风险（如有）：
[P559|Normal] 1. 启发式只满足 admissible、不满足 consistent 时，reopen 可能使展开次数超过 |V|，从而破坏机制 B 的 L 上限和终止证明。
[P560|Normal] 2. (f,h,node_id) 对节点具有稳定优先级，但若实现允许同一节点重复入队，仍需定义相同优先级条目的处理方式，否则路径前驱可能出现实现差异。
[P561|Normal] 3. G5 压测目前为 Windows x86_64 单机单线程；报告明确 R3/R4 未验，不能据此宣称跨平台或并发确定性已经成立。
[P562|Normal] 4. churn 场景没有预算让步，尚不能证明预算递增、stale recompute 和事务发布交错时仍然满足前向进展。
[P563|Normal] 5. CSR 的 u32 offsets 存在容量上限，必须定义溢出保护与原子重建失败语义。
