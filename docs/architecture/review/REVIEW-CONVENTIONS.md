# 评审流程常驻规矩（REVIEW-CONVENTIONS）

维护者约定（2026-11-19 起生效），适用于此后每一轮评审分享（ADR 裁决、阶段收口、专题评审）。

## 1. 分享链接给全

每份分享文案必须同时包含：

1. **仓库链接**：https://github.com/2222BUG/CitySim-rs
2. **RAW 链接**：被评审文件逐个给出（raw.githubusercontent.com 精确路径，中文文件名 URL 编码）——不得只给仓库首页（对方可能无法拼接路径）。
3. **ZIP 下载链接**：材料包直链 + 全量仓库 ZIP
   （离线 AI 可用附件形式转发材料包 zip）。

## 2. 报告者署名

要求每位报告者在报告中注明：**真实名字 / GitHub 昵称 / AI 模型名（三选一，可并列）**。
未署名的报告不计入裁决统计，只作参考意见。

## 3. 每轮至少一家代码级审查

（2026-11-19 追加，起因：ADR-NEW-24 第二轮评审八家中仅 QWEN4-MAX 做了代码级审查，
发现两条真实契约缺陷——溢出环绕违反 ADR-NEW-21、父边回溯取 min edge id；
其余七家均为条款级审查，未能发现。）

- 分享文案中明确要求：**请至少安排一位评审人做代码级审查**（通读被评审模块源码与测试，
  不只看条款文本）；或在任务书中指定某位评审人承担代码级审查。
- 代码级审查的发现必须给出**文件+行号级证据**（如 `lib.rs:182 wrapping_add`），
  未给出处的代码缺陷主张按"未见证据"处理。
- 代码级审查重点：实现与 ADR 条文的逐条对应、数值契约（溢出/舍入/边界）、
  测试是否覆盖声称的不变量、数据口径（分母/计数器语义）。
- 裁决汇总时，代码级审查发现的缺陷单独列出并要求工程侧修复+回归测试后回贴。

## 4. 裁决格式与回传

- 四选一：采纳 / 有条件采纳 / 拒绝 / 延后（拒绝和延后是合法裁决）。
- 引用条文编号与文件行号支撑每个判断；材料未覆盖的点标"未见证据"。
- 回传渠道：issue 或直接交维护者转贴；裁决原文归档 `docs/architecture/review/archive/`。
