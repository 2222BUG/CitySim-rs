# ADR-NEW-18：仿真参数基线与数值契约补充

- 编号：ADR-NEW-18（暂定编号，正式入仓时按仓库 ADR 序列重新编号并保留映射）
- 状态：Proposed
- 日期：2026-11-18
- 关联主文档章节：新增 2.10（仿真参数基线）、2.4（数值系统 SimScalar）、Spike A、Stage 0
- 来源：CitySim-rs V1.9.2 修订提案（五项）· 修订五；已并入技术方案 V1.9.3

## 背景

SimScalar 的格式（Q32.32、Q24.40 等）取决于具体范围需求，但 V1.9.2 没有给出需求参数。

## 问题

没有参数基线，数值方案和基准测试都无法定案，也无法比较不同人的测试结果。Spike A 的结论直接依赖这张表。

## 决策

先固定参数基线，再据此确定 SimScalar 格式。

### 参数基线表（数值全部待项目负责人确定；定案截止：Stage 0 前，先于三个 Spike）

| 参数 | 数值 | 影响 | 状态 | 定案方法 / 截止点 |
| --- | --- | --- | --- | --- |
| tick 频率 | 待定 | dt 的取值与累积误差 | 待确定 | 按目标模拟精度与负载折中从候选 10 / 20 / 30 Hz 选定；Stage 0 前定案（Spike A 前置，长期待定会卡死 Spike A） |
| 地图最大范围 | 待定 | 坐标所需的整数位数 | 待确定 | 按目标城市规模与坐标位宽需求推导；Stage 0 前定案 |
| 最小空间分辨率 | 待定 | 小数位数下限 | 待确定 | 按路网几何精度需求推导；Stage 0 前定案 |
| 最大速度与加速度 | 待定 | 乘法中间值范围 | 待确定 | 按交通模型物理上限推导；Stage 0 前定案 |
| 经济数值上限 | 待定 | 是否需要独立于 SimScalar 的整数类型 | 待确定 | 按经济系统设计值域推导；Stage 0 前定案 |
| 参考场景（Agent 数、路网规模） | 待定 | 基准测试的可比性 | 待确定 | 对齐 R2 门禁场景（10,000 Agent × 1,000 Tick）与大规模档位；Stage 0 前定案 |
| 最大持续运行 tick 数（最长连续运行时长） | 待定 | 中间乘法的位宽需求与长时漂移测试口径 | 待确定 | 按目标连续运行时长换算；Stage 0 前定案（V1.9.3 评审修订新增行） |

### 补充到 2.4 的数值契约

1. 权威时间用 u64 tick 计数，不用 SimScalar 秒累积。证据：Spike A 的 analysis.py 显示 Q32.32 以秒累积约 68 年后溢出。
2. dt 由 tick 频率经 from_ratio 一次性派生，并保留其舍入误差，写入黄金测试。
3. 乘除的舍入规则采用候选方案"就近舍入，0.5 向远离零取整"；analysis.py 显示截断会让误差单向累积。该结论目前仅来自 Python 模拟，Rust 实现尚未编译验证。
4. 经济数值如果超出 SimScalar 的整数范围，应使用独立的整数类型，不强行塞进 SimScalar。

## 考虑过的替代方案

| 方案 | 评价 |
| --- | --- |
| 先选定格式再回头约束需求 | 容易在后期发现范围不够，拒绝 |
| 先固定参数基线再定格式（采纳） | Spike A 结论有明确输入，测试可比 |

## 影响

- Spike A 的结论依赖参数基线表；参数基线补齐列为第零优先级（先于三个 Spike）。
- 参数确定后任何变更需要走 ADR。
- 权威时间 u64 tick 与 2.9 确定性边界第 7 条一致（联动 ADR-NEW-15）。
- 舍入规则的最终定案必须以 Rust 实测为准，不能只引用 Python 模拟结论。

## 验证方法

- 用确定下来的参数重跑 Spike A 的 analysis.py。
- 在 Rust 中做对应的范围与漂移测试（含 dt from_ratio 舍入误差黄金测试、长时间积分误差、溢出/饱和行为）。
- 舍入候选方案在 Rust 实现中验证误差是否不再单向累积。

## 证据范围声明

本 ADR 目前唯一的实验证据来自 Spike A 的 analysis.py（已运行的 Python 模拟）：Q32.32 秒累积约 68 年溢出、截断导致误差单向累积。所有阈值和数值均待验证，Rust 侧无实测数据。实验脚本与运行输出须随仓库入仓 docs/benchmarks/，否则证据不可复现（2026-11-18 评审修订，裁决：采纳）；当前 analysis.py 及其输出未随文档包提供，属待办事项。
