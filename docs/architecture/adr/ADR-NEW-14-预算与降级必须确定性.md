# ADR-NEW-14：预算与降级必须确定性

- 编号：ADR-NEW-14（暂定编号，正式入仓时按仓库 ADR 序列重新编号并保留映射）
- 状态：Proposed
- 日期：2026-11-18
- 关联主文档章节：2.7（LOD 与计算预算）、EC-04 / 3.4（降级机制与用户可见性）、Stage 2C、EC-11 / 4.6（R2 门禁）
- 来源：CitySim-rs V1.9.2 修订提案（五项）· 修订一；已并入技术方案 V1.9.3

## 背景

2.7 提出"预算即代码"，EC-04 提出三级降级（L1/L2/L3），但 V1.9.2 没有规定预算判断和降级触发的信号来源。

## 问题

如果按墙钟耗时、CPU 负载或帧率触发预算裁剪或降级，同样的输入在不同机器、不同负载下会走不同分支，导致权威模拟状态分叉，GlobalDigest 无法复现，R2 确定性门禁失去保护对象。

## 决策

权威预算只使用确定性工作量单位；墙钟时间只做遥测。具体条文：

1. 凡是会改变权威模拟状态的预算判断和降级触发，必须基于确定性的工作量单位，例如 A* 节点展开数、队列长度、本 tick 处理的实体数。
2. 墙钟耗时、CPU 负载和帧率只用于遥测与告警，不得参与改变权威状态的分支。
3. 每个有预算的系统必须声明：计量单位、每 tick 上限、超限行为（延后、分批或降级等级）、对应的诊断事件。
4. 如果需要按机器性能调整预算，只能在 tick 边界，通过显式配置变更完成，并且该变更必须写入存档和回放输入。
5. 降级的恢复条件同样用工作量单位定义。
6. LOD 层级切换与中、低精度层的更新同样会改变权威状态，其切换条件和更新频率必须使用确定性信号（如实体属性、确定性工作量单位）；墙钟耗时、负载、帧率不得作为切换依据。（评审修订补充，对应主文档 2.7）

## 考虑过的替代方案

| 方案 | 评价 |
| --- | --- |
| 按墙钟时间自适应 | 性能最好，但直接破坏确定性，拒绝 |
| 固定 tick 数上限 | 简单，但不能适应不同系统的成本差异，拒绝 |
| 确定性工作量单位（采纳） | 每个系统声明自己的计量单位，行为可复现 |

## 影响

- 每个高成本系统要先定义自己的计量单位，预算声明成为系统契约的一部分。
- 性能压力体现为"工作量上限内的延后"，而不是"自动变快"。
- 降级状态与预算滚动状态必须进入存档最小集合（联动 ADR-NEW-16 / EC-03）。
- 按机器性能的预算调整被收敛为显式、可回放的配置变更。

## 验证方法

- R2（PR 合并门禁）：单线程运行固定场景（10,000 Agent × 1,000 Tick），GlobalDigest 可复现；R2 只包含单线程基准与读档等价测试。
- R3（每日构建）：线程数无关性测试——同一场景在 1、2、8 线程下运行，以及人为注入延迟（模拟慢机器）场景，GlobalDigest 必须一致。
- R2 若需保留线程数无关性覆盖，应使用缩小场景（规模待实测确定）。
- 分层理由（2026-11-18 评审裁决，采纳）：线程数无关性叠加读档等价测试后，R2 门禁每次 PR 需 6 次以上全场景运行，耗时不可接受。验证条件：R2/R3 实测耗时记录于 docs/benchmarks/，若 R2 仍不可接受再行调整。
- 具体工作量上限阈值待实测后确定，本文档不预设数值。

## 修订记录（2026-11-18 评审修订，裁决：采纳）

- 评审建议 5：补充 LOD 切换确定性条款（决策第 6 条）——LOD 切换是改变权威状态的第三个入口，原条文只覆盖预算与降级。
- 评审建议 9：验证方法分层——线程数无关性测试由 R2 移至 R3 每日构建，R2 只跑单线程基准与读档等价测试；R2 如需覆盖用缩小场景。
- 评审建议 6：主文档 EC-04 开头"预算不足或资源压力较高"与确定性触发约束矛盾，修正为"工作量预算超限"（见主文档 3.4）。

## 正式裁决（2026-11-19）

- 裁决人与依据：项目负责人委托五家独立 AI 评审（报告 A/B/C/D/E）汇总，维护者代录；五家共识详见 decision-log《2026-11-19 正式裁决记录》。第 5 家（E）裁决方向与共识一致，但其证据引用不实（虚构 GlobalDigest-test、ADR-12 等），证据断言已驳回，不作验证依据。
- 裁决：**有条件采纳 → Accepted（附条件）**。
- 理由：确定性预算方向 5/5 成立；分歧仅在证据充分性（需实测降级一致性）。
- 验证条件（Stage 1 开工门禁）：①逐系统计量单位、每 tick 上限与 L1/L2/L3 映射的声明载体（债务 #16）定案；②降级触发/恢复路径实测一致性（降级切换前后同一输入摘要可复现）记录于 docs/benchmarks/；③机制 B 的预算递增属工作量驱动确定性规则、不触发条文 4 配置变更流程——此口径随 ADR-NEW-20 实施。

## Stage 2C 预算契约细化（2026-11-19，C2；同日决策3 投票定案）

- **声明载体（验证条件①，债务 #16 处置）**：代码注册表 `BudgetRegistry`（sim-core 新模块），
  每系统声明 `BudgetDecl { system_id, unit, per_tick_cap, overflow_behavior }`；本节表格为
  镜像记录；与 EC-12"契约即代码"一致，注册表随 crate 编译期检查。
- **计量单位与每 tick 上限（2026-11-19 决策3 投票定案，实测支撑见 docs/benchmarks/）**：

| 系统 | 计量单位 | 每 tick 上限（定案） | 超限行为 | 依据/投票 |
| --- | --- | --- | --- | --- |
| 寻路 sim-pathfinding | A* 节点展开数（TickBudget Q） | 65536 | 让步（Yielded，下 tick 续算） | 9 接受+1 附条件通过；含义=对实测 worst 398@40k 留余量的保险丝（非"100× 余量"——真实上界≈2\|V\| 由机制 B 让步与 TickBudget 兜底），100k Agent 档位须 R3 复核（千问Go!） |
| 路网事务 sim-network（拓扑） | 拓扑事务应用数（增/删边） | 1024 | 排队到下 tick | 1d 修改后定案（Claude：拓扑/代价分开） |
| 路网事务 sim-network（代价） | 纯代价事务应用数 | 1024 | 排队到下 tick | 同上 |
| 路网事务单笔工作量 | op 数+几何点数（edge_ops） | 8192 | 拒绝、下 tick 原样重试 | 1d 修改后定案（GPT-6：防一笔超大事务绕过预算） |
| 交通 sim-traffic | 本 tick 更新车辆数 | 活跃车辆全量（分片让步） | 分片让步（下 tick 续） | T-Bench-1 校准后回填 |
| 摘要/存档 sim-save | GlobalDigest 记录条目数 | 65536 | Fatal（存档不可信，SAV-0003） | 单存档条目数 <100 实测 |

- **L1/L2/L3 降级映射（EC-04 三级，触发信号=确定性预算消耗比例，禁墙钟）**：
  - **聚合口径（1b 修改后定案，MiniMax/GPT-6）**：消耗比例=逐系统比例取最严
    （max_i spent_i/cap_i，万分比），单系统饱和不被空闲系统稀释。
  - 阈值（定案）：L1 ≥70%、L2 ≥90%、L3 ≥100%（触发比较闭区间 >=）；恢复 <50%
    （开区间 <，迟滞防抖）。触发需连续 2 tick 超阈、恢复需连续 2 tick 低于恢复线
    （Claude：防单 tick 突发误触发/误恢复；trigger_ticks/recover_ticks=2 为随行定案值，
    调整须走 ADR 修订）。
  - L1：新寻路请求延迟入队（下 tick）、非权威细节更新暂停。
  - L2：让步档加封顶（B_k 更快达 L）、暂停经济等非紧急系统更新。
  - L3：仅维护已有状态（不接新请求），前向进展不变量兜底（ADR-NEW-20/17 条文 10）。
  - 降级等级、逐系统消耗比例、连续计数（over_streak/under_streak）、让步计数全部入
    存档与 GlobalDigest（G3 口径，sim-core budget 已实装）。
- **降级确定性验证（验证条件②）**：降级切换场景下注入延迟/改变线程数不改变摘要
  ——Stage 2B chaos 模式已验证（thread_independence + concurrent_stress 四组摘要一致）。

  恰 70/90/100/50 边界测试）；1d 修改后定案（拓扑/代价分开+工作量上限，已实装）。
  修改项以"多数要求的修改口径"定案；后续调整须走 ADR 修订流程。票面归档见
