# ADR-NEW-17：路网事务的过期结果策略

- 编号：ADR-NEW-17（暂定编号，正式入仓时按仓库 ADR 序列重新编号并保留映射）
- 状态：Proposed
- 日期：2026-11-18
- 关联主文档章节：EC-01 / 3.1（路网修改事务）、2.5（路网与路径搜索）、2.6（动态路网）、Stage 2C、Spike C
- 来源：CitySim-rs V1.9.2 修订提案（五项）· 修订四；已并入技术方案 V1.9.3

## 背景

EC-01 保证查询不会看到半更新的路网（原子发布），但没有规定"基于旧路网版本算出的寻路结果"在提交时如何处理。

## 问题

不同处理方式会产生不同的 Agent 行为，必须有统一契约，否则会成为确定性分歧的来源：全部接受可能让 Agent 走已不存在的边；全部重算在频繁修路时负载过高；处理顺序若依赖结果到达先后，则破坏确定性。

## 决策

以"影响区域相交判断"为默认策略，细节由 Spike C 的数据确定。具体条文：

1. 每个寻路请求记录 base_network_version；其结果携带同一版本号。
2. 路网事务必须声明影响区域，并随事务一起记录。
3. 提交结果时，如果当前路网版本不等于基准版本，候选处理策略为：
   - 影响区域与路径不相交：接受结果。
   - 影响区域与路径相交：重新入队重算，受预算和背压控制。
   - 重算次数超过上限：不得无限"丢弃-重请求"循环，进入前向进展兜底（见条文 10）。
4. 处理结果不得依赖结果到达的先后顺序；需要顺序时按请求 ID 排序。
5. 必须设置重算次数上限，防止在持续修路时出现活锁。
6. 需要单独定义：Agent 正在行走时，所在道路被删除怎么办（停止、回退还是就近重算）。
7. **聚合规则**（2026-11-18 评审修订，裁决：采纳）：当基准版本与当前版本之间存在多笔已发布事务时，相交判断针对该区间内全部事务影响区域的并集进行，而非只对最新一笔事务。
8. **影响区域覆盖范围**（2026-11-18 评审修订）：影响区域必须同时覆盖拓扑修改与动态代价更新（2.6 区分二者）；只覆盖拓扑修改是不完整的，动态代价变更同样可能使结果过期。
9. **语义保证边界**（2026-11-18 评审修订）：本策略只保证合法性（结果路径所经的边在当前路网中仍存在），不保证最优性（最优性由后续重寻路收敛）。
10. **前向进展不变量**（2026-11-18 评审修订）：Agent 的重算必须有界。无论路网如何持续修改，每个 Agent 必须在有限 tick 内获得可用路径或进入明确定义的受阻状态，不得出现无限"丢弃-重请求"循环（饥饿）。重算超限的兜底候选（由 Spike C 比选后以 ADR 定案）：局部可行路径 / 沿用旧路径有效段 / 标记受阻。EC-07 属性测试"过期寻路结果的重算次数不超过上限"保留。

## 考虑过的替代方案

| 方案 | 评价 |
| --- | --- |
| 全部重算 | 简单，但在频繁修路时负载高，拒绝作为默认 |
| 全部接受 | 可能让 Agent 走已不存在的边，拒绝 |
| 提交时逐边校验 | 精确，但成本随路径长度增长，作为候选保留 |
| 影响区域相交判断（采纳为默认） | 精确度与成本的折中，需 Spike C 数据支撑 |

## 影响

- 事务需要记录影响区域（EC-01 事务上下文扩充）。
- 寻路结果需要保存路径经过的区域信息。
- 重算入队消耗寻路预算，预算计量使用确定性工作量单位（联动 ADR-NEW-14）。
- 在途寻路请求（含基准路网版本）进入存档最小集合（联动 ADR-NEW-16）。
- 重算上限的具体数值待 Spike C 统计后确定，本文档不预设。

## 验证方法

- Spike C 增加"发布与查询交错"的并发测试。
- 统计固定场景下过期结果的数量和处理开销（接受 / 重算 / 丢弃的比例）。
- 持续修路压力场景下验证无活锁、重算次数不超上限，且满足前向进展不变量（每个 Agent 在有限 tick 内获得路径或进入受阻状态，无饥饿）。
- Agent 行走中道路被删除的三种候选行为（停止 / 回退 / 就近重算）做行为与确定性对比，结果以 ADR 修订定案。
- 重算超限兜底候选（局部可行路径 / 沿用旧路径有效段 / 标记受阻）在 Spike C 中做行为、确定性与实现代价对比，结果以 ADR 修订定案。
