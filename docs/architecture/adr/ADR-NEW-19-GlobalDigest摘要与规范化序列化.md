# ADR-NEW-19：GlobalDigest 摘要算法与规范化序列化

> 编号 ADR-NEW-19 为暂定编号，正式进入仓库裁决后重编号并保留映射（同 ADR-NEW-14 ~ 18 口径）。

- 状态：Proposed（草案，需按主文档第 7 章评审流程正式裁决）
- 日期：2026-11-18
- 关联主文档章节：EC-05（3.5）、EC-03（3.3）、EC-11（4.6）、2.9
- 来源：2026-11-18 设计审计（定义完备性审计第 1、11 条，均属未登记决策债务）。原"原 ADR：GlobalDigest 摘要语义（待完善）"在全语料中不存在文件，本 ADR 即其补建。

## 背景

GlobalDigest 是确定性验证体系的 oracle：R2 门禁（EC-11）、读档等价测试（EC-03/EC-11）、黄金测试基准、存档校验字段（EC-03 存档最小集"存档点 GlobalDigest"）全部以它为判据。但哈希算法、规范化序列化、纳入范围与计算时机在全部文档中均未定义（EC-05 只列了"必须明确"清单），"跑对了"当前无法判定。

## 问题

1. 用什么哈希？碰撞防护、跨平台位级稳定、速度三者如何取舍。
2. 什么字节布局进入哈希？同一状态的序列化顺序决定摘要稳定性；存档序列化格式与之直接耦合，必须一起定。
3. 摘要覆盖哪些状态、何时计算、版本如何演进。

## 决策

1. **哈希算法候选：BLAKE3-256（推荐）**。备选 xxh3-64（性能优先、碰撞防护弱）、SHA-256（慢）。选取理由：规范明确、跨平台位级一致（含 SIMD 实现输出与标量实现一致）、Rust 生态成熟。Spike 验证后定案。
2. **规范化（canonical）序列化**：小端字节序；定长整数直接写入（u8/u16/u32/u64/i64，按 schema 固定宽度）；变长数据先写 u64 长度前缀再写内容；**浮点不得进入摘要**（权威状态无浮点，2.9 条 3）；字段顺序由各模块 schema 固定并随 Schema 版本管理。存档与摘要**共用底层 canonical 编码规则**（字段编码、整数端序、可选值语义、字段顺序、稳定身份编码、版本标识规则），但**顶层 Schema 相互独立**：存档顶层 Schema 与 GlobalDigest 顶层 Schema 分别版本化、各自维护迁移/升级逻辑（存档需长期兼容迁移，摘要需稳定确定性语义，演进周期不同）；编码引入 **domain separation**（模块标识+数据类型标识进入编码流，避免不同类型数据编码歧义）（候选：自定义编码器，或 bincode 固定配置——须锁定整数编码与字节序，禁止默认配置）。（2026-11-18 外部评审 P0-04 修订：原"共用同一 canonical 编码器"口径收紧为共用编码规则、分顶层 Schema。）
3. **摘要版本字段 `digest_version`（u16）**：与"确定性协议版本"解耦但记录对应关系；哈希算法、纳入范围或编码变更必须 bump digest_version，旧黄金基准作废并重建。
4. **计算时机**：存档点全量重算（写入存档 GlobalDigest 字段，EC-03）；R2/读档等价以运行终点全量摘要为准；每 tick 滚动摘要为可选性能优化（滚动顺序必须确定性，且不得作为门禁判据）。
5. **纳入范围**：全部权威状态（按 2.9 权威/非权威划分），模块清单随 EC-05"关键模块摘要"补齐（候选模块：Agent、路网、寻路队列、经济、RNG 状态、预算与降级状态、时间与命令日志）。

## 考虑过的替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| xxh3-64 | 最快 | 碰撞防护弱于 BLAKE3，非密码学 | 备选 |
| SHA-256 | 防护最强 | 明显慢，验证场景不需要 | 否决 |
| CRC64 | 极快 | 防护不足 | 否决 |
| serde 默认序列化 | 生态现成 | 字段顺序/表示随类型演化漂移，非 canonical | 否决 |

## 影响

- 解锁：R2 oracle、读档等价测试、黄金测试基准、EC-03 存档校验字段。
- 存档格式与摘要编码器共用实现（与 ADR-NEW-20 的存档字段扩展协同）。
- 性能：全量哈希成本估计 1~5 ms/tick（10k Agent 全状态，估计值）；滚动摘要优化待实测记录于 docs/benchmarks/。

## 验证方法

1. 同一状态两次独立构造 → 摘要一致（canonical 性）。
2. 同状态在 x86_64 / aarch64 摘要一致（R4 前置）。
3. 修改任一权威字段 → 摘要变化（纳入范围完整性）。
4. 黄金摘要基准入 docs/benchmarks/（随 digest_version 管理）。
