# ADR-NEW-16：存档最小集合扩充

- 编号：ADR-NEW-16（暂定编号，正式入仓时按仓库 ADR 序列重新编号并保留映射）
- 状态：Proposed
- 日期：2026-11-18
- 关联主文档章节：EC-03 / 3.3（存档兼容）、EC-11 / 4.6（R2 门禁）、2.3（Agent 身份）、EC-02 / 3.2（RNG 隔离）
- 来源：CitySim-rs V1.9.2 修订提案（五项）· 修订三；已并入技术方案 V1.9.3

## 背景

EC-03 的最小兼容核心字段集只列了 AgentId、位置和核心状态语义等基础字段。

## 问题

缺少 AgentId 分配器高水位、当前 tick、在途任务和降级状态时，读档后的模拟会与不间断运行的结果分叉：

- 不保存分配器高水位 → 读档后可能复用已销毁的 AgentId，违反 2.3。
- 不保存降级等级与预算滚动状态 → 读档后预算/降级行为与存档前不同。
- 不保存寻路请求队列与未发布事务 → 在途工作的恢复语义不确定。

## 决策

采用下表作为最小兼容核心候选集，并增加读档等价测试：

| 类别 | 字段 | 说明 |
| --- | --- | --- |
| 元数据 | Schema 版本、WorldId、当前 tick（u64）、确定性协议版本 | 读档时先校验版本 |
| 身份 | AgentId 分配器的高水位 | 否则读档后可能复用已销毁的 AgentId，违反 2.3 |
| 随机数 | 全局种子、RNG 协议版本 | 若系统流由"种子 + 系统命名空间 + 事件键"派生，则不需要保存流内部状态；有状态的随机流必须保存其状态 |
| 路网 | 路网版本号、拓扑、动态代价 | 与路径结果的版本关联 |
| 在途任务 | 寻路请求队列（请求 ID、AgentId、基准路网版本）、未发布的路网事务 | 读档时的处理方式见下方条文 |
| 预算与降级 | 当前降级等级、预算滚动状态 | 否则读档后行为会与存档前不同 |
| 校验 | 存档点的 GlobalDigest | 读档后重新计算并比对 |

新增条文：

1. 存档点只能位于 tick 边界。
2. 在途任务采用"保存并恢复"（2026-11-18 评审修订定案，裁决：采纳）：存档包含在途寻路请求队列与未发布路网事务，读档后按原请求 ID、基准路网版本继续处理，不丢弃重新入队。理由：EC-11 读档等价测试（第 N tick 存档读档跑至 M 的摘要 == 直接跑至 M 的摘要）预设在途任务被恢复；若采用"丢弃并重新入队"，两次运行的处理序列不同，该测试在数学上不可能通过。若将来改用"丢弃并重新入队"，必须同步把读档等价测试降级为弱形式（两次独立的存档-读档运行之间摘要一致），并以 ADR 修订记录该变更。
3. 读档后必须执行一致性检查，并比对存档中的 GlobalDigest。

## 考虑过的替代方案

| 方案 | 评价 |
| --- | --- |
| 只保存世界快照、读档时重建所有派生状态 | 体积小，但重建结果难以保证与原运行一致，拒绝 |
| 扩充最小集合 + 读档等价测试（采纳） | 存档变大，但恢复行为可验证 |

## 影响

- 存档格式变大；Schema 迁移需要覆盖这些新增字段。
- 在途任务恢复策略已定案为"保存并恢复"（2026-11-18 评审修订），存档必须携带在途寻路请求队列与未发布路网事务的完整状态。
- RNG 存档需求依赖 ADR-NEW-02 / Spike B 的派生方案结论。
- 预算与降级状态入档依赖 ADR-NEW-14 的工作量单位定义。

## 验证方法

- **读档等价测试**（强形式）：在第 N tick 存档、读档，再运行到第 M tick，其 GlobalDigest 必须等于直接运行到第 M tick 的摘要。该测试与在途任务"保存并恢复"语义绑定（见决策条文 2）；若语义改为"丢弃并重新入队"，测试须降级为弱形式（两次独立的存档-读档运行之间摘要一致）。
- 此测试建议加入 R2 门禁（EC-11）。
- 读档后一致性检查 + 摘要比对失败时必须可诊断（联动 EC-08 错误分层）。

## 修订记录（2026-11-18 评审修订，裁决：采纳）

- 评审建议 1（读档等价测试与"丢弃并重新入队"互斥）：决策条文 2 由"二选一待定"定案为"保存并恢复"。理由与验证条件见决策条文 2 与验证方法（强/弱形式绑定关系）。
