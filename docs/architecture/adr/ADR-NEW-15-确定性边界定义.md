# ADR-NEW-15：确定性边界定义

- 编号：ADR-NEW-15（暂定编号，正式入仓时按仓库 ADR 序列重新编号并保留映射）
- 状态：Proposed
- 日期：2026-11-18
- 关联主文档章节：新增 2.9（确定性边界），回填 2.4、2.8、EC-02 / 3.2、EC-05 / 3.5、EC-12 / 4.7
- 来源：CitySim-rs V1.9.2 修订提案（五项）· 修订二；已并入技术方案 V1.9.3

## 背景

V1.9.2 多个章节在使用"确定性边界"一词（1.2 确定性目标、2.8 并行提交、EC-02 RNG 隔离、EC-05 GlobalDigest），但文档没有给出定义。

## 问题

没有定义，就无法判断某段代码是否违规，R2 门禁也不知道该保护什么；"确定性"停留在口号层面，无法转化为可检查、可测试的契约。

## 决策

采用以下八条作为确定性契约（主文档 2.9），并按 EC-12 尽量转为自动检查：

1. **范围**：首要目标是同一二进制、同一平台上的逐 tick 可复现。跨平台一致性列为 R4 发布前验证项，结论待验证。
2. **权威状态与非权威状态**：权威状态指影响后续模拟结果的数据；渲染、UI、遥测和调试数据属于非权威，不得写回权威状态。
3. **浮点**：权威系统不使用平台 f32/f64 运算。浮点语义必须用位级确定性实现（如软件浮点）并经 ADR 批准；渲染、UI、遥测可用平台浮点。以 f32 为基础的第三方库（如 Rapier）只能用于非权威侧，或经 ADR 豁免后承担权威物理并提供位级确定性证据。
4. **迭代顺序**：权威逻辑不得依赖 HashMap/HashSet 的迭代顺序，也不得假设 Bevy Query 的迭代顺序稳定。需要顺序时，按稳定键（如 AgentId）排序后再处理或提交。落地口径（2026-11-18 外部评审 P1-01 修订）：**规则目标是"禁止依赖无序迭代结果"，不是全面禁用容器**——已知 key 的查询/读取不依赖迭代顺序，属合法用途，可经 `#[allow]` 豁免加人工审查；clippy 类型级禁用作为第一道护栏保留（已实测有效），语义级约束（遍历后按遍历顺序提交权威状态）靠评审与属性测试覆盖。
5. **系统顺序**：影响权威状态的系统之间，必须显式声明 before/after 关系，不依赖调度器的偶然顺序。**全序提交与系统执行顺序分开定义**（2026-11-18 外部评审 P1-02 修订）：只对有数据依赖、写冲突或提交顺序要求的系统声明 before/after，无依赖系统保持并行；稳定提交全序键候选 `(phase_id, system_id, request_id, agent_id, local_sequence)`，字段按实际冲突模型定。
6. **并行**：并行任务只读取 tick 开始时的快照；结果按稳定键排序后串行提交。
7. **时间**：权威时间是 u64 tick 计数，不读取系统时钟。
8. **外部输入**：玩家命令必须带有生效 tick 编号，并记录下来以便回放。

## 考虑过的替代方案

| 方案 | 评价 |
| --- | --- |
| 只依靠代码评审 | 容易漏，无法形成门禁，拒绝 |
| 整个引擎使用统一的确定性容器 | 成本高，也可能削弱 ECS 的并行能力，拒绝 |
| 八条契约 + 契约即代码（采纳） | 明确边界，可逐步自动化检查 |

## 影响

- 权威代码对集合类型和迭代方式有约束（禁用无序容器的迭代顺序依赖）。
- 需要为稳定键排序提交预留开销。
- GlobalDigest 的纳入/排除范围（EC-05）以权威/非权威划分为准。
- 与 ADR-NEW-14（预算信号）、ADR-NEW-18（u64 权威时间）互为支撑。

## 验证方法

- 候选自动检查：clippy.toml 中的 disallowed-types / disallowed-methods 配置，用来禁止 HashMap 和系统时钟；具体可行性待验证。配置按 crate 分层（2026-11-18 评审修订，采纳）：权威模拟 crate 禁用 HashMap/HashSet 迭代顺序依赖与系统时钟，渲染、UI、遥测 crate 不受限，避免误伤非权威代码。
- Bevy 系统调度冲突审查：验证权威系统显式声明 before/after。
- 线程数无关测试：1、2、8 线程及注入延迟下摘要一致（与 ADR-NEW-14 共用）。
- 跨平台一致性：R4 发布前验证，当前不下结论。

## 修订记录（2026-11-18 评审修订，裁决：采纳）

- 评审建议 4（浮点禁令边界）：条 3 措辞由"不使用 f32/f64"改为"不使用平台 f32/f64 运算；浮点语义必须用位级确定性实现（如软件浮点）并经 ADR 批准"，与 SimScalar 选型未定（Spike A 可能需要浮点语义）解耦；补充 Rapier（f32 基础）只能用于非权威侧，或经 ADR 豁免承担权威物理并提供位级确定性证据。
- 评审建议 12（clippy 分层）：自动检查配置按 crate 分层，权威模拟 crate 禁用、渲染/UI/遥测 crate 不受限。

## 修订记录（2026-11-18 外部评审裁决）

- P1-01（HashMap 禁用口径）：**有条件采纳**——条 4 加落地口径：规则目标是"禁止依赖无序迭代结果"而非全面禁用容器，已知 key 的查询/读取属合法用途可经 `#[allow]` 豁免加人工审查；clippy 类型级禁用保留为第一道护栏（Step 7 已实测有效，docs/benchmarks/clippy-layering-REPORT.md）。
- P1-02（系统顺序与并行）：**采纳**——条 5 拆分"全序提交"与"系统执行顺序"两个概念，稳定提交全序键候选 `(phase_id, system_id, request_id, agent_id, local_sequence)`，只对有依赖/写冲突的系统声明 before/after，无依赖系统保持并行。
