# ADR-NEW-20：请求/事务 ID 分配器与在途寻路任务口径

> 编号 ADR-NEW-20 为暂定编号，正式进入仓库裁决后重编号并保留映射（同 ADR-NEW-14 ~ 18 口径）。

- 状态：Proposed（草案，需按主文档第 7 章评审流程正式裁决）
- 日期：2026-11-18
- 关联主文档章节：EC-01（3.1）、EC-03（3.3）、EC-11（4.6）、2.8、2.9 条 8
- 来源：2026-11-18 设计审计（定义完备性审计第 2、3 条，均属未登记决策债务）。二者互锁，合并为一个 ADR 裁决。

## 背景

EC-01 规定过期结果处理"按请求 ID 排序"（稳定排序键），EC-03 存档最小集只保存 AgentId 分配器高水位、不保存请求 ID/事务 ID 分配状态。ADR-NEW-16 定案"在途任务保存并恢复"并绑定 EC-11 强读档等价测试（第 N tick 存档读档跑至 M 的摘要 == 直接跑至 M）。

## 问题

1. 读档后新请求若复用旧请求 ID，稳定排序键次序改变 → 提交顺序不同 → 强读档等价测试失败。事务 ID 同理（EC-01 路网事务）。
2. "在途寻路任务"是否包含 A* 搜索中间态（open/closed 表）未定义：若读档后重做已展开的搜索工作，节点展开数不同 → 每 tick 工作量预算消耗不同 → 延后/降级分支不同 → 摘要分叉，**强读档等价测试可能数学上不成立**。ADR-NEW-16 论证了"丢弃并重新入队"不可能通过强测试，但"恢复请求、丢弃搜索进度"存在同类风险。

## 决策

1. **请求 ID、事务 ID 分配器**：与 AgentId 同款确定性分配器——全局单调递增 u64 计数器，**高水位随存档保存**（EC-03 存档最小集增补两字段：请求 ID 分配器高水位、事务 ID 分配器高水位）。任何稳定排序键不得在读档后复用旧 ID。
2. **在途寻路任务口径（推荐方案③，待裁决）**：**寻路为单 tick 原子任务**——A* 搜索不跨 tick 保留中间态；节点展开达到每 tick 上限时确定性中止（产生确定性失败/让步事件），请求按确定性策略于后续 tick 重试。与既有"存档点仅 tick 边界"（EC-03）规则组合后，tick 边界不存在部分搜索状态，存档只需保存请求队列（请求 ID、AgentId、基准路网版本），**强读档等价天然成立**：直跑与读档跑在同一 tick 以同一预算处理同一批请求，工作量消耗逐 tick 对称。
3. **预算计量**：中止尝试已消耗的节点展开数照常计入当 tick 工作量预算（两运行对称消耗，不影响等价性）；中止事件必须产生诊断事件（EC-08 口径）。

## 考虑过的替代方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| ① 存档含部分搜索状态（序列化 open/closed 表） | 允许跨 tick 搜索，续算不丢工作 | 存档 schema 重且与 A* 实现强耦合；A* 内部结构演化破坏存档兼容 | 备选（Spike C 若证明必须跨 tick 搜索则切换） |
| ② 预算计量对重做工作幂等 | 存档轻 | 幂等记账难以在通用预算框架（ADR-NEW-14）下保证 | 否决 |
| ③ 单 tick 原子搜索 + tick 边界存档（推荐） | 与既有规则自然组合，强等价天然成立，schema 最简 | 单次搜索受每 tick 预算上限约束；预算紧张时重试开销（确定性、可观测） | **推荐** |
| （不设分配器高水位，请求 ID 由内容哈希派生） | 无需存档字段 | 哈希碰撞与内容变化导致 ID 不稳定，排序键失效 | 否决 |

## 影响

- EC-03 存档最小集增补两个分配器高水位字段（与 AgentId 高水位并列）。
- 2.8 请求/结果数据结构须含请求 ID（u64）；结果携带 base_network_version（既有条文）。
- 方案③下"请求超时/重试"策略必须确定性（按请求 ID 与 tick 推导），并与 ADR-NEW-17 的重算上限/前向进展兜底协同。

## 验证方法

1. 强读档等价测试（EC-11 R2）直接验证本 ADR 的核心断言。
2. 属性测试：任意存档-读档交错下请求/事务 ID 全局唯一且单调（EC-07）。
3. 中止-重试循环的确定性回放测试（含持续修路场景，覆盖 ADR-NEW-17 前向进展不变量）。

## 预算让步与前向进展（2026-11-18 外部评审修订：P0-01 采纳、P0-02 有条件采纳）

外部评审指出决策 2 的单 tick 原子搜索存在饥饿风险：若单次搜索所需展开节点数长期大于每 tick 预算上限，"中止—从头重试"每 tick 重复相同的展开工作，请求可能永远无法完成。ADR-NEW-17 条文 10 的前向进展不变量只覆盖"路网持续修改"轴，未覆盖"预算让步"轴。本节补齐。

决策补充：

1. **双计数器分离**：`budget_yield_count`（因预算不足中止让步）与 `stale_recompute_count`（因路网版本过期重算）**不得共用同一重算上限**，各自独立计数、独立终止条件；搜索规模大的请求不得被误判为"过期/受阻"。
2. **前向进展不变量（预算轴）**：无论单次搜索规模如何，请求必须在有限 tick 内完成或进入明确定义的受控终止状态，不得无限"中止—重试"循环。
3. **预算状态生命周期**（P0-02）：任务按请求 ID 稳定序处理；同优先级先进先出+稳定序；优先级与等待状态以模拟 tick 表示；预算是否跨 tick 累积及其上限必须明确（与 ADR-NEW-14"预算滚动状态"、decision-log 债务 #20 为同一问题，随本 ADR 一并定案）；预算队列与任务顺序影响未来模拟结果，属权威状态，**入存档（EC-03）并入 GlobalDigest 纳入范围（ADR-NEW-19）**；设最大等待 tick 上限与超限行为（衔接 Agent 受阻状态）。

候选机制（裁决前比选）：

| 方案 | 机制 | 优点 | 缺点 |
|---|---|---|---|
| A 跨 tick 续算 | 保留 open/closed 表续算 | 真续算、零重复展开 | 与决策 2 方案③矛盾，存档 schema 重（即上文替代方案①） |
| B 确定性预算递增 | 重试按 `budget_yield_count` 确定性放大节点上限 | 不存搜索状态、与③兼容 | 重复展开有界存在，最坏开销需实测 |
| C 规模上限+受控失败 | 超单次搜索最大规模即受控失败/替代路径 | 实现最简 | 大路网有效路径可能被拒 |

默认候选 **B**（与决策 2 方案③兼容），A 为 Spike 证明必要时的切换路径（同替代方案①切换条件），C 与 ADR-NEW-17 条文 10 兜底（局部可行路径/沿用旧路径有效段/标记受阻）协同。随本 ADR 正式裁决定案。

验收清单：

1. 构造单次搜索需求超每 tick 预算的固定场景（固定输入/路网/随机种子）。
2. 请求在有限 tick 内完成或进入可解释的终止状态。
3. 不同执行调度下无无限重复计算（EC-07 属性测试：`budget_yield_count` 有界）。
4. 预算让步状态可存档/恢复且不改变未来调度（强读档等价测试覆盖含让步路径的场景）。
5. 中止/递增/重试全程产生确定性事件，不破坏确定性。
6. `budget_yield_count` 与 `stale_recompute_count` 分离计数并各自有界。
